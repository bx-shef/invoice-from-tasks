# Архитектура

> Last reviewed: 2026-10-07

Как устроено приложение и почему так. Правила расчёта — `docs/PROCESSING.md`, настройки —
`docs/SETTINGS.md`, вызовы REST — `docs/REST_METHODS.md`.

## Стек

Nuxt 4 (SPA, `ssr: false`) + `@bitrix24/b24ui-nuxt` (интерфейс) + `@bitrix24/b24jssdk` (REST из
фрейма и с сервера) + Nitro (наш `/api`) + `openai` (транспорт к BitrixGPT). Как в эталонах
`client-bank-alfa-by` и `ai-price-import`.

**Один артефакт.** В эталоне client-bank статика отдаётся nginx, а backend — отдельно. Здесь
серверной работы мало, поэтому один Nitro-сервер отдаёт и страницы, и `/api`. Проверено на
сборке: сервер отвечает `200` и на `GET`, и на `POST` к страницам — Битрикс24 открывает
обработчики POST-запросом, и отдельный трюк nginx (`error_page 405 =200`) не нужен.

Что nginx эталона делал попутно, у нас делает Nitro или общий прокси (сверено 2026-09-25):
- кэш скриптов и стилей `/_nuxt` на год (`immutable`) — Nitro по умолчанию;
- сжатие — `nitro.compressPublicAssets`: `.gz` и `.br` при сборке, самый большой скрипт — 234 КБ →
  62 КБ; общий nginx-proxy сам не сжимает;
- соединения к Node без keepalive — метка `keepalive=disabled` в `docker-compose.prod.yml`: nginx
  эталона держал соединение дольше прокси, а без него прокси ловил закрытые Node соединения —
  `502` на POST из портала;
- таймаут долгих ответов — `make proxy-timeout` для нашего домена;
- лимиты запросов — в самом приложении (`server/utils/requestLimits.ts`, `rateLimit.ts`).

**SPA, а не SSR.** Все рабочие страницы живут во фрейме портала, SEO им не нужно; SPA
избавляет от гидрации с редиректами. Настройки окружения (`NUXT_PUBLIC_SITE_URL`) подхватываются
при запуске — проверено на сборке, пересборка образа под другой адрес не нужна.

**Выкат — как в client-bank.** `main` → образ в GHCR → Watchtower на сервере → общий nginx-proxy с
TLS Let's Encrypt, адрес `https://invoice-from-tasks.bx-shef.by` (`docs/DEPLOY.md`). Образ один
на любой сервер; единственный build-arg — коммит сборки для `GET /api/health`. Проверка сервера
одной командой — `make doctor`.

## Страницы (`app/pages/`)

| Путь | Когда открывается | Что делает |
|---|---|---|
| `/` | прямая ссылка | публичное описание приложения |
| `/install` | установка приложения в портал | права, встройка, типы полей «Код доступа» и «Вебхук клиента» (если их нет), подписки на события, `installFinish` |
| `/app` | «Приложения» → «Счёт из задач» | состояние настроек, как пользоваться, вход в настройки |
| `/settings` | из `/app` | общие, ставки, наценки, НДС, поля клиента (#34), публичная страница (#34), промпты, доступ, хранилище |
| `/invoice` | карточка счёта → верхняя кнопка → «Заполнить из задач» | выбор источника и типа, предпросмотр, запись, консультации |
| `/p-<домен портала>/i-<ID счёта>` | **публичная**, по ссылке или QR-коду на счёте (#34) | клиент вводит код доступа → `/api/public/invoice` → расшифровка: клиент, исполнитель, дата, стадия, строки «[123-456] …» с суммами, задачи (заголовок со ссылкой, описание, результат, номер задачи клиента со ссылкой в его портал, если известен домен). Стадия не из списка в настройках — показывается фраза из настроек |
| `/uf/access-code` | поле «Код доступа» в карточке компании или контакта (встройка `USERFIELD_TYPE`) | код из 10 символов: «Сгенерировать», «Перегенерировать», «Отозвать» (#34) |
| `/uf/client-hook` | поле «Вебхук клиента» там же | ввод вебхука → `/api/client-hook/seal` шифрует → в поле; задан — «указан для <домен>» и «Стереть» (#34) |

Все, кроме `/`, `/p-…` и `/uf/*`, обёрнуты в `InPortalGate`: вне фрейма показывают «откройте в Битрикс24».
**Публичная страница счёта** — единственное место, где портал читается без сотрудника: сервер
ходит в портал **токеном установщика** (осознанное исключение из «права CRM не расширяем», решение
владельца в #34) и только по верному коду (`server/utils/publicInvoice.ts`):
- лимиты: 10 попыток с IP за 10 минут, 600 на портал в час; **неверных** кодов на счёт — 100 в час
  (верный код счётчик не тратит). Компромисс: посторонний со ссылкой с бумажного счёта может
  заблокировать клиента на час, только потратив сотню попыток; код (~58 бит) этим всё равно не
  подобрать. Счётчики — в памяти процесса (один экземпляр сервера);
- до верного кода в портал уходят 2 запроса: счёт и один пакет `batch` с компанией и контактами;
  код сравнивается в постоянное время со всеми клиентами; «нет портала», «нет счёта» и «не тот код»
  — один ответ 404 с выровненным временем (не меньше 800 мс); сбой портала — 503, не «неверный код»;
- настройки, стадия, строки и задачи — только после верного кода; задача из строки «[123] …»
  показывается, только если она привязана к этому счёту или его сделке (`UF_CRM_TASK`) — номер в
  названии строки может вписать кто угодно;
- цена просмотра: ~5 запросов + страницы позиций (до 4) + пакет задач + по запросу результатов на
  задачу (до 20); всё в одной очереди токена установщика с записью ставок. Готовая расшифровка
  кешируется на 2 минуты (код проверяется всегда);
- текст задач — без HTML (BB-код снимается, страница выводит текстом); `no-store`, `noindex`;
- **задача клиента** (этап 4, `server/utils/clientPortal.ts`): вебхук портала клиента — из поля
  «Вебхук клиента» компании или контактов счёта; берётся только вебхук того портала, чей домен
  указан в задаче (поле `clientFields.taskDomain`). Вебхук расшифровывается на сервере (ключ
  `CLIENT_HOOK_ENC_KEY`, привязка к нашему порталу, проверка домена: любой внешний, внутренние адреса отсекаются — `isPublicHookHost`) и наружу не уходит.
  Портал клиента — чужой: только https, без редиректов, общий дедлайн 10 с на просмотр, ответ до
  2 МБ потоком (обрыв до чтения в память), BB-код снимается и текст выводится как текст (HTML
  экранирует Vue), аватар — только с самого портала клиента (иначе — пиксель слежки). Задачи —
  одним `batch` `tasks.task.get` (постановщик, статус, дата закрытия), результаты — v3 по 4 запроса
  одновременно, до 20 задач; на портал — одна попытка за просмотр. Сбой портала клиента страницу
  не роняет — остаётся ссылка на задачу, причина — в журнале (без адреса вебхука). Состояние
  словами владельца: 5 — «принята» (с датой `closedDate`), 4 — «требует принятия», 1–2 —
  «поставлена», остальное — как в карточке.
  ⚠ **Номер задачи клиента** — только из поля нашей задачи (`clientFields.task`), а не из названия
  строки: эта задача уже проверена на привязку к счёту. Проверить, что задача клиента относится к
  нашему счёту, в портале клиента нечем — поэтому сотрудник, который может править нашу задачу,
  может вписать в поле номер другой задачи клиента, и её увидит тот, у кого есть код счёта.
  Смягчение: вебхук клиента — только с правом `task` и от сотрудника клиента, который видит лишь
  задачи для нас (это и рекомендация клиенту при выдаче вебхука).
- **PDF документов** (этап 5, `POST /api/public/document`): на странице — последний документ счёта
  по каждому шаблону из настроек (`publicPage.templates`), только с готовым PDF. Скачивание — POST
  с кодом в теле (не в адресе): та же проверка доступа, что у страницы (код, стадия, лимиты, общие
  счётчики неверных кодов — `server/utils/publicContext.ts`; по IP у скачиваний своё окно, 60 за
  10 минут — клиент с верным кодом качает несколько документов). Скачать можно только документ,
  показанный на странице (последний по шаблону этого счёта), а не старую версию перебором ID.
  `pdfUrlMachine` (ссылка с токеном) — только https на сам портал, без редиректов, до 20 МБ,
  сигнатура `%PDF-`. Клиент получает файл, ссылка с токеном наружу не уходит. Превью документа —
  `imageUrlMachine` тем же запросом с `kind: 'image'` (PNG/JPEG по сигнатуре), миниатюра на странице —
  кнопка скачивания PDF. Сбой списка
  документов страницу не роняет — блок пуст, причина в журнале. Превью грузятся параллельно;
  код доступа — поле-пароль (`type=password`, `autocomplete=current-password`, логин — домен портала):
  сохраняет менеджер паролей браузера, кнопка с глазом показывает код (пример b24ui «With password toggle»).
- **Режим согласования** (решение владельца 2026-10-06): одна стадия счёта (`publicPage.approvalStage`,
  в обычных стадиях её быть не может — разбор настроек убирает). В ней клиент видит расшифровку и:
  пишет комментарий (`POST /api/public/comment`) — универсальное дело на ответственного за счёт со
  сроком +1 час; ответ клиенту — заметка к делу, закрытое дело — с отметкой «Закрыто»; жмёт
  «Согласовать» (`POST /api/public/approve`) — галка и момент в поля счёта из настроек, дело
  ответственному. Пишет сервер **токеном установщика** — второе исключение из «права CRM не
  расширяем» (у клиента нет фрейма). Лимит — 20 действий на счёт в час, текст до 2000 символов,
  BB-коды обезврежены. Комментарии всегда свежие — не из кеша расшифровки.
- **Чат проблем** (как в client-bank-alfa-by): групповой чат из настроек; пишет бот приложения
  (`imbot.v2`, `server/utils/problemChat.ts`: ленивая регистрация, вступление в чат), без права
  `imbot` — `im.message.add` токеном установщика; одно сообщение на ключ в час: 5-й неверный код к счёту за час, блокировка
  после 100, сбой записи комментария или согласования. Сбой чата вход не ломает.
- **Ссылки для печатных форм**: документы приложение не создаёт. `GET /qr/<домен>/<ID>.png`
  (`server/routes/qr/`) — PNG с QR-кодом адреса страницы, без кода доступа и без чтения портала,
  поэтому открыт всем (генератор документов берёт картинку по ссылке без авторизации). Домен — только
  из разрешённых порталов. Встройка счёта при открытии пишет правами сотрудника адрес страницы и адрес
  картинки в поля счёта из настроек (`publicPage.linkField`, `publicPage.qrField`; `useInvoiceLinks`),
  только если значение другое. Поле картинки владелец вставляет в шаблон как изображение.

### Экономика задач и счёта (решение владельца 2026-10-07)

- **«Стоимость работ»** (UF задачи, `taskFields.workCost`): итог строки с налогом — в счёт уходит
  ровно он (`fixedGross` → `toProductRows`), цена без налога — обратным счётом (`netOfGross`).
- **Задача без времени** — не стоп: предупреждение, часы оценивает BitrixGPT (`POST /api/ai/estimate`,
  `shared/domain/estimate.ts`: опытный разработчик с ИИ-агентом, без завышений; промпт правится в
  настройках — `prompts.estimate`, формат ответа добавляет приложение), ставка — на сегодня.
- **Сравнение** (`shared/domain/economics.ts`): формула (часы × цена часа) против выставленного, обе
  суммы С НДС (владелец 2026-10-07: «1500 — это я выставил»; «Стоимость работ» — как записана). По «Собрать строки» разница, % и дельта пишутся в UF задач (`tasks.task.update` пакетом), итог —
  JSON в поле счёта своего типа «Экономика счёта» (`ift_economics`, страница `/uf/economics`: сводка,
  пометки и «Пересчитать», который спрашивает источник и тип расчёта и прогоняет тот же сбор без записи
  строк). Пометки: убыток и завышение строго больше порога (`economics.threshold`, 20%), «нет данных» —
  оценка ИИ или нет ставки.
- Поля создаёт «Создать поля приложения»; своё поле «Стоимость работ» владельца выбирается в настройках.

### Справка и ИИ-чат (по принципу toolsai)

- **Публичная и внутренняя документация.** Публичная — `docs/guide/NN-*.md` (белый список по имени,
  `isPublicGuideFile`), Nitro кладёт только этот каталог в серверный ассет `assets:kb`
  (`nuxt.config.ts → nitro.serverAssets`): внутренние `docs/*.md` в образ не попадают. Гард
  `tests/kb.test.ts`: справка не ссылается на внутренние документы.
- **Страница `/help`** — раскладка как у сайта документации toolsai (helpdesk, владелец 2026-10-07):
  шапка с поиском по разделам, меню на `B24DashboardSidebar` (сворачивается), статья на белом листе
  (крошки, «В статье:», «Назад / Дальше»), оглавление со слежением и «Обсудить с ИИ», панель чата
  справа, плавающее «Спросить ИИ». Данные — `GET /api/kb/pages`, markdown — `markdown-it` без сырого
  HTML, якоря — `headingOf`. Чистые функции — `app/utils/helpLayout.ts`, стили — `app/assets/css/help.css`
  под `.hd-shell`. Отличия от toolsai: системный шрифт, без тёмной темы, ответ целиком (не поток).
- **ИИ-чат** (`POST /api/kb/chat`, только из фрейма; свой лимит — 30 вопросов за 10 минут на
  сотрудника и 300 в час на портал, `KB_CHAT_LIMITS`: заполнение счетов он не отнимает): фрагменты
  страниц по `##`/`###`, BM25 с облегчённым русским стеммером (перенос `toolsai/site/server/rag/core.mjs`
  в `shared/domain/kb.ts`), до 16 фрагментов в 24 000 символов, обсуждаемая страница — первой;
  системный промпт — только по справке, ссылки на её разделы. Ответ — целиком, не потоком (наш
  транспорт BitrixGPT без стриминга); история — в памяти страницы, последние 10 сообщений.
  Качество поиска — `tests/kb.test.ts` (вопрос → нужная страница в контексте).
- **Подсказки FAQ в слайдере** (как в client-bank-alfa-by): `<HelpLink anchor="…">` →
  `openSliderAppPage({ place: 'app-help-<якорь>' })`; портал открывает главную страницу, `app.vue`
  по `place` (`helpRouteForPlace`, якорь — по формату) переходит на `/help?p=90-faq#якорь`. Своя
  встройка не нужна. Отказ портала — обычный переход. Гард: каждый якорь `HelpLink` есть в FAQ.

`/uf/*` живут внутри поля высотой 60 px — без обёртки: вне фрейма просто пусты. Значение поля они
пишут правами сотрудника: в режиме редактирования — в форму (`placement.setValue`, сохраняет
карточка), в режиме просмотра — сразу `crm.item.update` (`app/utils/fieldPlacement.ts`).

```

                   (единицы измерения), useUsers, useStorageProbe (замер места)
app/components/    интерфейс на b24ui
server/api/        наш API: события портала, запись настроек и ставок, BitrixGPT — тонкие

server/middleware/ заголовки страниц (CSP) и пределы запросов к /api
server/utils/      проверка фрейм-токена, SSRF-гард, хранилище токенов, клиент REST, LLM,
                   пределы запросов
```

## Кто и какими правами ходит в портал

| Действие | Откуда | Чьими правами |
|---|---|---|
| Чтение счёта, задач (с тегами, v2), результатов задач (REST v3), времени, курсов валют, единиц измерения; запись товаров и дела в счёт | фрейм | сотрудник, открывший окно |
| Чтение настроек | фрейм | сотрудник (разрешено всем) |
| Запись общих настроек | сервер | администратор (его фрейм-токен) |
| Запись ставок | сервер | администратор — своим токеном; редактор — токеном установщика |
| Замер места | фрейм | администратор |

Ключевое свойство: товары в счёт пишет **сотрудник своими правами** — приложение не расширяет
его доступ к CRM. Токен установщика используется в одном месте — запись ставок редактором.

## Безопасность сервера

- **Кто пришёл** (`server/utils/frameAuth.ts`): `Authorization: Bearer <фрейм-токен>` и
  `X-B24-Domain`. Домен — через SSRF-гард; портал обязан быть в хранилище установок (иначе ключ
  BitrixGPT был бы открыт любому порталу); токен проверяется вызовом `profile` и `app.info.CODE`
  (фрейм-токен чужого приложения на том же портале тоже прошёл бы `profile`). `B24_APP_CODE`
  обязателен: без него — `503`, а не пропуск проверки. Решение кэшируется на минуту по хэшу
  токена (полный кэш вытесняет старые записи, а не сбрасывается целиком); живых проверок — не
  больше 60 в минуту с одного IP (поток случайных токенов иначе гонял бы сервер в чужие порталы).
- **BitrixGPT** (`server/utils/aiGateway.ts`, `aiRequests.ts`): ключ только на сервере; промпты
  берутся из настроек портала, а не из запроса; лимит — в двух измерениях: 120 запросов и 3000
  строк счёта на сотрудника за 10 минут, 1200 запросов и 30 000 строк на портал за час,
  консультация весит 25 строк (в памяти процесса — при нескольких экземплярах нужен общий
  счётчик); сырой текст провайдера наружу не отдаётся.
- **Установка** — `docs/B24_EVENTS.md`: `member_id` и домен сверяются с OAuth-грантом на
  облачном сервере авторизации портала (из белого списка; коробка сервером авторизации не
  бывает); оба токена установщика хранятся зашифрованными (AES-256-GCM). Токен установщика
  читается заново на каждый вызов, вызовы одного портала идут по очереди с таймаутом 60 с
  (`installerCall.ts`) — refresh-токен одноразовый, а зависший запрос не должен блокировать портал.
- **Пределы запросов**: тело POST к `/api` — до 64 КБ (события) и 512 КБ (остальное), без
  `Content-Length` — `411` (`server/middleware/requestLimits.ts`); события установки и удаления —
  до 60 в минуту с адреса (IPv6 — с /64), посторонние события не считаются; сверок установки —
  до 600 в минуту всего, списывается перед запросом к серверу авторизации (`b24EventsHandler.ts`).
  IP за прокси — последний адрес `X-Forwarded-For` при `TRUST_PROXY=1` и только от соединений из
  частной сети; `/api/health` показывает, учтён ли заголовок (`docs/DEPLOY.md`). Счётчики чистятся
  по окну каждого ключа и ограничены 20 000 ключей (`rateLimit.ts`) — поток с тысяч адресов не
  съест память и процессор.
- **Запись в портал из фрейма** — без автоповторов SDK при сетевых сбоях (`app/config/b24.ts →
  sdkRestrictionParams`): запрос, выполненный порталом с опоздавшим ответом, иначе ушёл бы ещё
  раз — дубли строк счёта, дел и пунктов меню.
- **Заголовки страниц** (`server/middleware/securityHeaders.ts`): `frame-ancestors` только для
  порталов Битрикс24; `X-Frame-Options` не ставится — он запретил бы и портал.

## Токен фрейма

SDK обновляет токен только на пути своих запросов. Токен уходит и на наш сервер, поэтому
`useApi` перед запросом обновляет его, если жить ему меньше минуты
(`app/utils/frameToken.ts`). Опция `keepAuthFresh` из документации b24jssdk в установленной
версии 2.2.0 отсутствует — проверено по типам пакета.
