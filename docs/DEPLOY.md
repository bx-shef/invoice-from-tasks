# Развернуть и подключить к порталу

> Last reviewed: 2026-09-24

## 1. Сервер

Нужен публичный **https**-адрес: портал открывает страницы приложения во фрейме и шлёт события
на `/api/b24/events`.

```bash
cp .env.example .env        # заполнить (см. ниже)
docker compose up -d --build
curl -s https://<адрес>/api/health   # какие настройки окружения заданы (без секретов)
```

Образ — один контейнер (`Dockerfile`): Nitro отдаёт страницы и `/api`. Токены установки
лежат в `/app/.data` — там смонтирован том `portals` (`docker-compose.yml`). Без тома
пересоздание контейнера их потеряет, и запись ставок не-администраторами перестанет работать до
переустановки приложения на портале.

`docker-compose.yml` публикует порт **только на `127.0.0.1:3000`**: HTTPS и доступ снаружи даёт
обратный прокси (nginx, Caddy, Traefik) на этом же сервере. Прокси на другой машине — замените
на `"3000:3000"` и закройте порт сетевым экраном: порт, доступный мимо прокси, позволяет обходить
лимиты по IP.

### Переменные окружения

Полный шаблон с комментариями — `.env.example`.

| Переменная | Зачем | Без неё |
|---|---|---|
| `NUXT_PUBLIC_SITE_URL` | адрес для обработчиков встройки и событий | установка возьмёт адрес из браузера |
| `B24_CLIENT_ID`, `B24_CLIENT_SECRET` | сверка установки и обновление токена установщика | установка **не сохраняется** (`docs/B24_EVENTS.md`) — не работают BitrixGPT и запись ставок редакторами |
| `B24_TOKEN_ENC_KEY` | шифрование токенов установки — access и refresh (`openssl rand -hex 32`) | установка падает с `500` |
| `B24_APP_CODE` | принимать фрейм-токены только своего приложения; код показывает администратору главная страница приложения, пока переменная не задана | **`503` на все запросы из фрейма**: BitrixGPT, сохранение настроек и ставок |
| `TRUST_PROXY` | `1` — сервер за своим обратным прокси: лимиты считаются по IP клиента | лимиты по IP общие для всех, кто за прокси (адрес прокси один) |
| `VIBE_API_KEY` или `BITRIXGPT_API_KEY` | BitrixGPT (ключ Вайбкода `vibe_…`) | режим названий «BitrixGPT» и консультации отвечают ошибкой |
| `B24_APPLICATION_TOKEN` | фиксированный `application_token` | первый `ONAPPINSTALL` задаёт токен портала |
| `B24_SELFHOSTED_HOSTS` | коробочные порталы вне `*.bitrix24.*` для SSRF-гарда | к ним сервер не пойдёт; ⚠ установка из коробки всё равно не сохраняется — приложение облачное (`docs/B24_EVENTS.md`) |

⚠ **Копия `B24_TOKEN_ENC_KEY` — вне сервера** (менеджер паролей, хранилище секретов). Потеря или
смена ключа делает сохранённые токены нечитаемыми: запись ставок редакторами перестанет работать
на всех порталах до переустановки приложения. Ротации ключа пока нет (`server/utils/secretCrypto.ts`).

### Пределы запросов

`server/middleware/requestLimits.ts`, значения — `server/utils/requestLimits.ts`:
- тело POST к `/api`: события портала — до 64 КБ, остальное — до 512 КБ; больше — `413`;
- без заголовка `Content-Length` — `411` (тело неизвестной длины пришлось бы читать целиком).
  Браузер и портал его шлют; ⚠ для событий портала это проверяется после выката
  (`docs/project-map.md`);
- события установки и удаления — до 60 в минуту с одного адреса (IPv6 — с сети /64), `429`;
  прочие события не считаются: они ничего не стоят, а иначе чужой портал мог бы выжечь лимит и
  заблокировать чужие установки;
- сверки установки — до 600 в минуту всего: каждая — исходящий запрос к серверу авторизации с
  нашими `client_id`/`client_secret`; мусор и удаления этот потолок не тратят;
- живые проверки фрейм-токена — до 60 в минуту с одного адреса (IPv6 — с /64), `429`;
- BitrixGPT — в двух измерениях: 120 запросов и 3000 строк счёта за 10 минут на сотрудника,
  1200 запросов и 30 000 строк за час на портал; консультация весит 25 строк
  (`server/utils/rateLimit.ts`).

HTTPS обычно даёт обратный прокси перед контейнером — тогда `TRUST_PROXY=1`, иначе все запросы
выглядят пришедшими с адреса прокси. Берётся **последний** адрес `X-Forwarded-For` (его дописывает
прокси), поэтому схема рассчитана на один прокси. Заголовку верим, только если соединение пришло
из частной сети (свой прокси, мост Docker): клиент из интернета подставить себе адрес не сможет.
Проверка: `curl -s https://<адрес>/api/health` через прокси — в ответе `request.forwardedFor`
должно быть `used`; `ignored` — заголовку не верим (нет `TRUST_PROXY=1` или прокси ходит к
приложению не из частной сети), и все клиенты делят лимиты адреса прокси.

## 2. Приложение в портале

Локальное приложение (для своего портала) или приложение в кабинете разработчика Маркета:

| Поле | Значение |
|---|---|
| Путь обработчика (основная страница) | `https://<адрес>/app` |
| Путь для первоначальной установки | `https://<адрес>/install` |
| Права (scope) | `crm`, `task`, `catalog`, `user_brief`, `placement` |
| Режим «только API» | выключен — у приложения есть интерфейс |

Название поля «Путь для первоначальной установки» — из документации
(«Мастер установки локального приложения»); подписи остальных полей в интерфейсе портала
могут отличаться формулировкой.

⚠ Право задач — **`task`** (не `tasks`): так его принимает портал (`docs/REST_METHODS.md`).

После сохранения портал выдаст `client_id` и `client_secret` — это `B24_CLIENT_ID` и
`B24_CLIENT_SECRET`. Код приложения (`app.info → CODE`) — в `B24_APP_CODE`. Пока переменная не
задана, главная страница приложения (`/app`) показывает администратору портала этот код и список
того, что не настроено на сервере (по `GET /api/health`). Задайте переменную и перезапустите
контейнер — до этого BitrixGPT, настройки и ставки отвечают `503`.

## 3. Установка и первая настройка

1. Установить приложение — откроется `/install`: проверит права, зарегистрирует пункт
   «Заполнить из задач» в карточке счёта, подпишется на события, завершит установку. Недостающие
   права покажет списком.
2. Проверить, что сервер готов: `GET /api/health` → все флаги `config` (кроме `trustProxy`
   без прокси) — `true`. Порталы он не показывает; что установка дошла, видно по тому, что
   `/api/rates` и BitrixGPT перестали отвечать `409 portal not installed`.
3. Администратор: «Приложения» → «Счёт из задач» → «Настройки»:
   - «Хранилище» → «Замерить предел» (**на тестовом портале**, `docs/SETTINGS.md`);
   - «Общие» → валюта ставок, округление, режим названий;
   - «Ставки», «Наценки», «Промпты», «Доступ».
4. Открыть счёт → верхняя кнопка карточки → «Заполнить из задач».

## Смена адреса сервера

Переустановите приложение (или откройте `/install` из портала): установка снимет встройку и
подписки на события со старым адресом (`placement.unbind`, `event.unbind`) и зарегистрирует новые.
Если приложение уже установлено, `installFinish` не вызывается — страница только обновит
встройку и подписки.
