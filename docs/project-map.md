## Ворота перед боевым порталом

Пока не пройден живой прогон установленного приложения, оно **не ставится на рабочий портал** с
настоящими счетами: запись в счёт необратима (`docs/AGENT_RULES.md` §5.8). REST расчёта и записи
уже проверен на тестовом портале вебхуком (🔌, `docs/REST_METHODS.md` — ✅), установка и
`app.option` — из установленного приложения (2026-09-25). Не проверено: права сотрудника во
фрейме, встройка в карточку счёта, BitrixGPT из приложения. Прогон — по `docs/DEPLOY.md` §3.

## Дальше

1. **Живой прогон в приложении на тестовом портале** ([#2](https://github.com/bx-shef/invoice-from-tasks/issues/2)).
   Сервер поднят, приложение установлено (2026-09-25). Уже подтверждено: событие установки
   дошло до сервера и сохранено; `/api/health` через прокси — `forwardedFor: used`; предел
   `app.option` замерен (256 КиБ без потерь, `docs/SETTINGS.md`); администратор сохраняет ставки
   (фрейм-токен → наш сервер → `app.option.set`), значит `B24_APP_CODE` задан верно. Подсказку
   с кодом приложения на главной (пока `B24_APP_CODE` не задан) отдельно не проверяли.
   REST расчёта и записи уже проверен вебхуком и повторяется смоком (`pnpm smoke`, 2026-09-25):
   задачи и фильтры, теги (из v2-списка задач), записи времени и их листание, курсы, запись позиций (заменить и добавить, пакет с ошибкой),
   дело консультации, имена сотрудников — всё сошлось с кодом; найдено одно расхождение — пустые
   названия единиц измерения (исправлено). Остаётся то, что видно только из приложения,
   порядок — `docs/DEPLOY.md` §3:
   - какой код привязки (`SI_<id>` или `T1f_<id>`) ставит сам интерфейс, привязывая задачу из
     карточки счёта (REST находит оба);
   - правами обычного сотрудника во фрейме: **запись позиций счёта** (`crm.item.productrow.set` /
     `.add` — самое чувствительное место: пишет сотрудник своими правами), `crm.currency.list`,
     `tasks.task.result.list` v3 (вебхук был администраторский);
   - сервер авторизации отвечает на продление токена установщика — видно по записи ставок
     сотрудником-редактором (не администратором) через час после установки; если есть портал
     другой зоны (`.com`, `.de`) — какой сервер авторизации он называет;
   - дело консультации: `DESCRIPTION_TYPE = 3` рисует разметку, переносы строк на месте;
   - «добавить к товарам» при отказе посередине — счёт перечитывается, «добавлено N из M»;
     при медленном портале строки не задваиваются (повторы SDK на записи выключены).
