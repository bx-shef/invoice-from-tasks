## Ворота перед боевым порталом

Пока не пройден живой прогон, приложение **не ставится на рабочий портал** с настоящими счетами:
всё про REST сверено с документацией, но не с порталом, а запись в счёт необратима
(`docs/AGENT_RULES.md` §5.8). Прогон — на тестовом портале по `docs/DEPLOY.md` §3; по итогам
статусы в таблицах выше и в `docs/REST_METHODS.md` меняются на ✅.

## Дальше

1. **Живой прогон на тестовом портале** — всё выше пока 🧪. Порядок — `docs/DEPLOY.md` §3.
   Заодно замерить и записать сюда:
   - предел `app.option` (кнопка «Замерить предел»);
   - код привязки задачи к счёту (`SI_<id>` или `T1f_<id>`);
   - ответ `tasks.task.result.list` на `/rest/`;
   - как портал принимает `task.elapseditem.getlist` с позиционными параметрами;
   - установка доходит до сервера: событие приходит с `Content-Length` (иначе `411`), в нём есть
     `auth[server_endpoint]` и он из белого списка, сервер авторизации отвечает на продление,
     `client_endpoint` — адрес портала; если есть портал другой зоны (`.com`, `.de`) — какой
     сервер авторизации он называет;
   - главная показывает администратору код приложения, пока `B24_APP_CODE` не задан;
   - `/api/health` через свой прокси показывает `request.forwardedFor: used`;
   - дело консультации: `DESCRIPTION_TYPE = 3` рисует разметку, переносы строк на месте;
   - «добавить к товарам» при отказе посередине — счёт перечитывается, «добавлено N из M»;
     при медленном портале строки не задваиваются (повторы SDK на записи выключены).
2. Решения, помеченные ⚙ в `docs/PROCESSING.md` — подтвердить или поменять.
3. Генерация документа по задачам — владелец опишет отдельно.

## Что мешает

- **Нет доступа к тестовому порталу из сессии агента.** Всё про REST сверено с документацией
  (MCP), но не с живым порталом — поэтому пункт 1 «Дальше» первый.
- **Предел `app.option` не известен.** По документации ядра — 2000 символов; пока не замерен,
  приложение считает по нему, и длинные свои промпты не сохранятся.
